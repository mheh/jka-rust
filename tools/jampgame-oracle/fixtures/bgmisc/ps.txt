# --- snap=0 leaves origin/viewangles untouched (the pos/apos copy path) ---
# NOTE: snap=1 is deliberately NOT tested here. Under the harness's mandatory
# -D__linux__ (chosen only to dodge q_shared.h's uncompilable MSVC __asm
# SnapVector), bg_misc.c binds the `#define SnapVector(v) {(int)v...}` TRUNCATION
# macro. The port's snap_vector models the RETAIL x87 `fld/fistp` ROUND-to-
# nearest (q_shared.h:1408 — every compilable macro branch truncates; only the
# uncompilable Windows __asm rounds), matching retail JA and the reference
# oracle_c harness (which redefines SnapVector to round). This platform-ifdef
# rounding-mode split cannot be arbitrated by an unedited-TU __linux__ build, so
# snap=1 is excluded (porting-rules §19); the non-snap copy path is covered.
reset
ps pm_type 0
ps health 100
ps genericEnemyIndex -1
ps origin 0x42c96666 0xc2851eb8 0x41c9999a
ps viewangles 0x42b7999a 0x42360000 0xc2360000

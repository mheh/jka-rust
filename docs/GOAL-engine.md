# Goal — pure-Rust dedicated MP engine (`openjkded`)

> Status (2026-07-24): COMPLETE. The `jampDed` link set is transcribed,
> integrated, and closed (zero stubs, zero `TODO: Port`, zero extern
> forward-decls); the pure-Rust server boots, loads maps, runs the game dylib,
> and has hosted live players since 2026-07-12, gated by the lockstep-referee
> suite (9 scenarios incl. real-map mp/duel1 + ffa1, oracle-vs-rust
> byte-identical). Closure and boot rulings DEC-13…
> DEC-23. The checklist below is kept as the historical campaign record; the
> active track is now the client port (`docs/plans/2026-07-24-client-port/`).

Build the Rust implementation of the codemp dedicated-server engine: a host
that loads the existing game module dylibs (Rust or Raven-oracle, unmodified)
and answers every syscall byte-identically to the C `openjkded`, verified
differentially at every step.

Scope is total: **every function of the `WinDed.vcproj` Release link set —
110 sources, 2,481 functions, 87,728 LOC — ports 1:1.** No subsystem is
stubbed, deferred, or cut: the VM interpreter and JIT emitter, botlib, ICARUS,
RMG, NPCNav, the null client-stub layer, and the headless renderer
model/shader loader all port. The only boundaries are seams, not deferrals:
the `Sys_*`/`NET_*` platform layer (implemented natively in Rust) and vendored
zlib/png (Rust crates, fixture-gated).

Plan: `docs/plans/2026-07-08-mp-engine-build-out.md`. Port order:
`tools/closure-prototype/out/engine/engine-port-order.{json,tsv,md}`,
generated by `tools/closure-prototype/engineorder.py` — the machine-verified
total dependency order (27 waves; port in `seq` order and no symbol is ever
referenced before it is ported).

## Ground rules (hard, user-directed 2026-07-09)

- [ ] **No `todo!()`, no stub bodies, no `TODO`/`FIXME` markers at any commit
  during the port.** The dependency order makes placeholders unnecessary; a
  porter who cannot finish a function escalates instead of stubbing.
  `grep -rn "TODO\|FIXME\|todo!"` over the engine crates stays empty at every
  commit.
- [ ] **No "port later" (ruling 34).** The pre-campaign scaffolding markers
  (48 census 2026-07-09: lifecycle `todo!` bodies, LIFE-Q8 boot no-ops,
  DEV-GLUE provisionals, host-struct field markers) are enumerated in-scope
  work for THIS campaign: each maps to a wave, a §F doc, or an in-campaign
  design ruling (`ZeroValid`, LOAD-Q1, ctx injection). The campaign is not
  complete while any remains; nothing is re-deferred.
- [ ] **The order comes only from the tool.** `engineorder.py` under its
  pinned parse configuration (plan appendix) is the single source of the port
  order; fix the tool and regenerate, never hand-edit the artifact.
- [ ] **Transcription-first.** Faithful port, parity green, refactor behind
  the passing diff (porting-rules §A2). No safety-idiom conversion during the
  port; the safe-state migration is a separate post-parity phase, as for
  `mp_game`. Structural conventions decided at port time: file-scope globals
  → host-struct fields (never `static mut`); C++-track subsystems (icarus,
  RMG, ghoul2/renderer class internals) take the §F design-first shape;
  `unsafe` confined to the ABI seam.
- [ ] **Every function is verified against the oracle** by at least one of:
  golden fixtures (3a), captured-replay fixtures (3b), or subsystem A/B
  swap-in (3c) — before its subsystem is declared complete.

# Audit gh#31 step-009 - the FX mini-refent packet

The auditor read every oracle cite, the live Rust ground, DEC-66, and the gh#31 hand-forwards before it opened the packet. Every quote below comes from that pass.

## Row 4 - the state home (mechanical)

**Cleared.** DEC-66 ruling 1 places the persistent `Rng` and the `sh1`/`sh2`/`f_count` statics "beside the backend's frame-to-frame state" (`docs/decisions.md:1540`), and `Pipeline3d` is that state ("this is render-thread-owned state", `crates/mp/renderer-gpu/src/pipeline3d.rs:905-906`). `RendererFrontend::rng` exists where the packet cites it (`crates/mp/renderer/src/renderer_frontend.rs:117`, "The renderer's own LCG (ruling 21 keeps it off the engine island's)") and sits on the frontend side of the DEC-50 split, so not reusing it is right. `TrSurfaceShapeState` lives at `crates/mp/renderer/src/tr_surface.rs:50-53` with exactly `sh1` and `sh2` today, and `mp_renderer::tr_surface` is a public module (`crates/mp/renderer/src/lib.rs:35`), so the import path in the contract resolves. `Rng::new()` seeds `crt_holdrand: 1` (`crates/native/math/src/rng.rs:127-132`), the MSVC compile-time seed DEC-66 names.

## Row 5 - the dead fork branch (mechanical)

**Cleared.** `grep -rn f_count oracle/codemp/` returns exactly the three hits the packet claims: the declaration `static float f_count;` (`oracle/codemp/renderer/tr_surface.cpp:956`), the guard read (`:1100`), and the decrement (`:1104`). The sweep covers the whole MP tree - game, cgame, client FX, renderer - so no FX or game writer exists. SP assigns `f_count = 3;` at `oracle/code/renderer/tr_surface.cpp:844`, and SP's own declaration is `static f_count;` (implicit int, `:642`) against MP's `float`. The short-circuit instruction is correct and load-bearing: the guard reads `( e->renderfx & RF_FORKED ) && f_count > 0 && Q_random(&e->frame) > 0.94f && ...` (`:1100`), so with `f_count` at zero the `Q_random` draw never runs and the seed never advances. A transcription that evaluates the draw eagerly would shift the seed stream even though the branch stays dead.

## Row 6 - the `oldorigin` write (mechanical)

**Challenged in part.** The default action is right and the alternative is closed: DEC-66 ruling 2 fixes the dispatch at an immutable entity borrow, so a local `end` is the only shape. The write is confirmed at `oracle/codemp/renderer/tr_surface.cpp:1159`, `VectorMA( start, perc * dis, fwd, e->oldorigin );`, read straight back at `:1160`.

The challenged part is the sentence "It is parity, not a divergence." The oracle's write does survive past one draw chain inside a frame: a mirror or portal scene runs `R_RenderView` per view, both views' draw surfaces index the one shared `backEnd.refdef.entities` array, and the second `RB_SurfaceElectricity` call of the frame reads the `oldorigin` (and the `frame` seed) the first call mutated. The packet's own justification, "no oracle read outlives the frame either," is true only at the frame boundary, not between two views of one frame. No committed golden and no current backend path draws a portal view, so nothing observable changes today, but the note at the site should not claim strict parity. Recommended wording: parity for single-view frames, with the multi-view double-draw named as an accepted cosmetic gap under the DEC-66 ruling 3 umbrella. The same caveat attaches to the DEC-66 ruling 2 seed premise and is flagged here as evidence, not re-litigated.

## Row 7 - the vertex cap on a long bolt (mechanical)

**Cleared.** `RB_CHECKOVERFLOW( 4, 6 )` sits at the top of `DoLine2` (`oracle/codemp/renderer/tr_surface.cpp:662`) and flushes the tess batch at the cap, and this backend builds into unbounded `Vec<WorldVertex>`/`Vec<u32>` with `u32` indices and no flush point. A dead-fork bolt emits 12 vertices per 20-unit step (one `ApplyShape`, three `DoLine2` quads), so only a bolt past roughly 1,600 units approaches `SHADER_MAX_VERTEXES` at 1000. No cap, no flush, and a pause trigger on approach is the consistent disposition, and inventing a mid-surface split would be the real risk.

## Claim verification

**Confirmed - MP never assigns `f_count`.** See row 5. The sweep covered `oracle/codemp/` in full, not just the renderer.

**Confirmed - `RB_SurfaceElectricity` writes its own input entity's `oldorigin`.** `oracle/codemp/renderer/tr_surface.cpp:1159-1160`. See row 6 for the multi-view caveat the packet's parity framing misses.

**Confirmed - the zero-duration `RF_GROW` divide.** `perc = 1.0f - ( e->axis[0][2] - tr.refdef.time ) / e->axis[0][1]` (`:1147`) with a zero divisor yields an infinity for a nonzero numerator, which the two clamps catch, and a NaN for a zero numerator, which passes both `perc > 1.0f` and `perc < 0.0f` as false and propagates into the geometry. Rust `f32` arithmetic produces the same values, so parity holds with no rule-19 note. Confirmed exactly as written.

**Confirmed - the macro multi-eval sites and the RNG call order.** The `#if 1` at `oracle/codemp/game/q_shared.h:1352` selects the macro forms, `VectorScale` at `:1361` and `VectorMA` at `:1365` each expand `s` once per component, and the three deviation lines (`tr_surface.cpp:1075-1077`) therefore draw nine `Q_crandom` values per loop step in component order 0, 1, 2 per line. The float-width section is also correct: the seeded family stays `f32` end to end, and `Rng::crandom` returns `f64` (`rng.rs:212`) to carry the double-typed `crandom()` expression to its narrowing store.

## Contract and bundle findings

The surface contract is closed and minimal. Every listed item has a consumer in the commit bundle, every helper the arms call either exists (`do_line`, `do_sprite`, `add_quad_stamp_ext` at `:4499`, `:4465`, `:4425`) or is on the list, and the import mapping resolves against the real module surfaces (row 8). No missing item was found for the draws themselves, and nothing on the list is unused.

One gap in the commit staging: commits 1 through 3 leave `refdef_time`, `rng`, and `shape` unused inside `build_entity_geometry`, because no arm consumes them until commit 4 (commit 5 for `rng` via the hilt draw, commit 4 via `create_shape`). Unused-parameter warnings would fail the zero-warning gate on three consecutive commits. The packet gives the lane no instruction for the window, and "no draw changes" plus the pause discipline bar improvisation. One amendment line fixes it, for example a `let _ = (refdef_time, &rng, &shape);` in the wildcard arm placed by commit 1 and removed by commit 4, or underscore-prefixed parameter names renamed when consumed.

One optional observation, not a defect: the `tr_surface.rs` doc comments for `CreateShape` (`:107-110`) and `RB_SurfaceSaberGlow` (`:1218-1225`) still state that the renderer has no RNG receiver, which DEC-66 ruling 1 superseded. The contract's comment-edit list does not name them, though the "comment edits only" write scope would permit the fix. The session may fold them into the commit-4 note edits or leave them for a later pass.

The bundle gates are exact and runnable: the crate name matches, all four world goldens are `#[ignore]`d so the `--ignored` invocation reaches them, the scene suite is un-ignored so its plain invocation reaches everything, the hud pair covers both halves, and every invocation carries `--test-threads=1` per the serial rule. The fixture arithmetic across commits (fifteen, seventeen, one moved, eighteen) is consistent with the goldens directory. The lockstep-referee waiver is sound: no commit touches `mp_game`, the server, or a `jampded` link-set crate.

Rows 1 through 3 are user rulings and are not ruled here. No evidence was found that changes their framing: the `mp_renderer` twin is confirmed dead at every leaf row 1 names, the saber-glow stand-in and its re-bless mechanics are as row 2 states, and the bless flow and defect conditions in row 3 match the verified harness.
